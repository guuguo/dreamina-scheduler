# v0.2.4

## Merge Summary

本次版本是后台调度的**性能与稳定性专项**：在空闲期消除对 `state.json` 的全量读写并改用 Condvar 唤醒，显著降低空闲 CPU/能耗；同时修复进程被 kill/崩溃/强退后遗留陈旧 `queue.lock` 导致调度永久卡死的严重故障；并对历史数据做裁剪与压实，控制 `state.json` 体积无界增长。全程测试先行（TDD），新增 23 个 Rust/JS 测试。

## Changes

- **空闲短路**: `should_process_now` 判定无活跃任务时跳过重函数，消除空闲期对 `state.json` 的全量读写与 `tick`/`no_due_task` 噪音日志。
- **Condvar 唤醒**: `SchedulerWaker` 将不可打断的 `sleep` 换为 `wait_timeout`，入队（`create`/`update_task_command`）即时 `notify` 唤醒；空闲自适应间隔 30s→60s，灵敏度由唤醒兜底；单次快照复用，避免一个 tick 内重复读盘。
- **前端签名门控**: 新增 `get_state_signature`（仅 `stat` 不读内容），30s 轮询比对签名未变则跳过整份 `get_app_state`。
- **紧凑序列化**: `persist` 改用 `to_string`，防止 pretty 格式膨胀。
- **数据治理**: `cap_execution_history` 裁剪 `query_records`（留 30）/`attempts`（留 50）无界增长；`AppStore::load` 一次性压实旧的大文件，结果/状态完整保留。
- **陈旧锁回收（修复永久卡死）**: 新增 `lock_is_stale`，对 `created_at` 超阈值（600s，> 提交超时 300s）或无法解析的 `queue.lock` 判为陈旧；`try_acquire_store_queue_lock` 检测到陈旧锁时回收重试，新鲜外部锁仍正确阻塞，避免误抢正在干活的进程。崩溃/强退/kill/断电后调度最多 10 分钟自愈，不再永久卡死。
- **回归测试**: 新增锁层与主入口测试（含端到端 `process_queue_recovers_from_stale_lock_end_to_end`），补上此前完全缺失的测试盲区；性能优化侧新增 16 个 Rust/JS 测试。

## 实测收益（同机真实数据）

- 空闲期零写盘；空闲 CPU 较旧版 **−46%**。
- `state.json` 体积 **35.5MB → 17.9MB（−50%）**，裁剪为主因。
