## 已确认结论

- 提示词在前端改为「富文本 doc(JSON) 为 source of truth + 派生纯文本 prompt + 素材引用列表」双表示。
- MCP `dreamina_queue_video` / `dreamina_queue_videos` **一行不改**；富文本仅前端内部表示，向下游恒等导出纯文本 + paths。
- 本轮只产出文档与原型，不落代码。
- 输入媒体扩展仅限音频。
- 任务优先级：C(引用稳定+可预览) > D(顺序/名字对齐) > B(最近使用置顶) > A(粘贴音频)。

## 推荐假设（P2，不再向用户提问，写入 plan）

- **A1「最近使用」口径**：当前 `isRecent` 只看 `created_at`（创建 3 天内），不是真正的"用过"。推荐新增 `last_used_at`：素材被任务引用/入队时打点；素材管理器默认按 `last_used_at` 倒序，并在「全部」视图顶部固定一行"最近使用"。
- **A2 名字统一口径**：编辑器显示 `item.label`（带角色前缀的友好名），右侧 Thumb 显示 `asset.name`（库原始名），二者源不同导致对不上。推荐统一以"显示名 = label 口径"为主标题，`asset.name` 作为副标题/hover，两侧一致。
- **A3 顺序统一**：以富文本 doc 中 mention 出现顺序为唯一真相；右侧预览按同一顺序渲染（不再各自按数组顺序），并在编辑器删除 mention 时同步移除对应 id。
- **A4 音频粘贴落点**：粘贴音频 → 落为一个临时音频素材（类比临时图片 `temp_image`）→ 进入 `audio_asset_ids` 并在右侧"音频"区显示、可试听，可作为 @mention 引用。
- **A5 富文本存储兼容**：任务新增可选字段 `prompt_doc`(TipTap JSON)；老任务/ MCP 任务无该字段时，fallback 用现有 `parseInlineContent` 从纯文本重建（与今天行为一致，不退化）。
