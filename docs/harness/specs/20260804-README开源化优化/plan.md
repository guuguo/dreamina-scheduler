## 目标

以优质开源项目的方式重构项目根 README，让首次访问仓库的人在首屏理解「不间断排队」的核心价值，明确桌面端与 Agent/MCP 都能入队，并通过真实界面、隔离演示数据截图快速确认主要能力与运行边界。

## 用户与场景

- 目标用户：需要批量生成即梦视频、厌倦手动等待并发窗口和反复查询结果的创作者、Agent 与自动化使用者。
- 主要场景：一次准备多个视频任务，让应用在运行期间持续排队、重试、查询并推进后续任务。
- 关键用户路径：安装并登录 Dreamina CLI → 创建任务 → 加入队列 → 保持应用运行 → 在任务中心查看排队、重试、查询与结果。

## 不变项

- 业务语义：README 只描述仓库中已经存在且可由代码或界面确认的能力。
- 事务边界：不修改任何任务提交、重试、查询或持久化逻辑。
- 调度与并发：不改变现有队列、双车道、重试与自动查询策略。
- 数据与事实源：以当前代码、测试和已有需求文档为事实源；截图只使用隔离演示数据。
- 核心实现：不改写应用功能代码。

## 已确认事实

- 用户要求按优质开源项目方式优化 README，突出不间断排队并提供重点功能截图。
- 当前实现会持续处理本地队列，识别并发限制后自动等待重试，并自动查询远端任务结果。
- 当前设置支持 macOS `caffeinate` 与 Windows `SetThreadExecutionState` 防止系统自动睡眠；App 退出后队列不会继续执行。
- 当前任务中心展示共享等待池、标准/Fast 车道、任务状态、过程记录和结果入口。
- 当前项目内置 `dreamina-mcp` stdio Server；Agent 可单个/批量入队、原位更新任务、查询快照和推进一次队列。
- MCP 与 App 共用 `DREAMINA_SCHEDULER_HOME`；MCP Server 本身不运行常驻调度循环。
