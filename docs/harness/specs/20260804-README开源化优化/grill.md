## 当前理解

- 需求目标：把 README 重构成对首次访问者友好的开源项目首页，把不间断排队放在第一价值位，并让 Agent 用户能通过 MCP 愉快接入。
- 本期成功标准：首屏价值明确、真实截图可见、能力与边界准确、快速开始可执行。
- 不变项：不改功能、不改变调度语义、不使用真实用户数据截图。
- 已确认故障证据：现有首屏价值分散、没有功能截图、睡眠边界陈旧、存在乱码。
- 最小闭环：README 重写 + 隔离演示截图 + 链接/命令/事实检查。
- 主要非目标：产品功能开发、Harness 升级、发布安装包与动态徽章。

## 已确认结论

- 不间断排队是首屏主叙事，角色与素材能力作为提高批量生产效率的辅助能力。
- 截图必须来自当前正式界面，且使用隔离演示数据。
- 必须明确 App 运行、防休眠和退出后的能力边界。
- 必须区分“App 常驻自动调度”和“纯 MCP 需调用 `dreamina_process_queue_once`”，不能让用户误以为 stdio Server 自带常驻 worker。

## 第一性原理与复杂度审查

| 检查项 | 结论 | 依据/处理 |
| --- | --- | --- |
| 是否先写清业务语义、事务、调度、事实源和核心实现的不变项？ | 是 | 只改文档和截图，不改任何运行语义 |
| 首期每个问题是否都有直接证据或强制约束？ | 是 | 用户请求、README 现状和代码路径均可核对 |
| 是否优先包裹故障边界，而不是重写内部？ | 是 | 只在 README 表达层修复 |
| “能优化”和“必须修复”是否已经分开？ | 是 | GIF、Release 下载与徽章后置 |
| 是否新增表、第二事实源、状态、队列、并发、线程/连接或核心重写？ | 否 | 仅文档与静态图片 |
| 删除任一新增机制后，最小闭环是否仍能通过 P0 验收？ | 否 | 删除截图或首屏主叙事都会直接违反用户要求 |
| 本轮评审主要是在补缺口，还是持续删除过度设计？ | 补缺口 | 范围保持为 README 最小闭环 |
