## 当前理解

- 需求目标：将当前即梦调度器从 App 主导的排队工具，演进为一个与即梦 CLI 调用方式尽量一致的 Python 队列代理，供 agent/skill/脚本调用。
- 本期成功标准：形成清晰需求文档和技术方案，能指导后续实现 `dreaminaq` MVP。
- 主要非目标：不重写即梦 API，不继续建设复杂桌面工作台，不让 skill 承担后台 worker。

## 已确认结论

- 主线从桌面 App 转为 headless CLI 队列代理。
- Python 可以作为新主实现语言，但只做队列代理，不重写即梦 API。
- 调用协议应尽量贴近即梦 CLI。
- Skill 是调用说明和工作流规则，不是执行/轮询主体。
- 缓存需要包括素材、任务/提交和结果三层。
- 夜间长时间调度和防休眠/保活是第一版 P0，不是后续优化。

## 推荐假设

- 第一版只实现命令行和 JSON 输出，不做 Web/TUI。
- 新数据目录用 `~/.dreaminaq/`，与旧 App 数据目录隔离。
- SQLite 是任务状态和并发锁的唯一事实源。
- 结果复用默认关闭，显式 `--reuse exact` 才开启。
- macOS 首版使用 `caffeinate` 实现防休眠；Windows/Linux 保留适配接口和能力声明。
