# 需求拷问：即梦队列独立技能项目化

## 状态

- 状态：confirmed-with-open-details
- 最近确认时间：2026-07-06
- 用途：记录已经拷问清楚的产品边界，以及执行前仍需确认的问题。

## 已确认回答

### Q1：这个项目还要不要继续做成桌面 App？

回答：第一版不要以桌面 App 为主。

理由：用户现在更多是 MCP/agent 调用提交任务，不是手动创建任务。GUI 可以以后做轻量查看，但核心价值在 CLI/skill/脚本可复用。

### Q2：它和即梦 CLI 的关系是什么？

回答：它是即梦 CLI 外面的队列增强层。

边界：

- 使用官方即梦 CLI 完成真实上传、提交、查询、鉴权。
- 新项目负责缓存、排队、重试、Fast 兜底、记录查询和 agent 友好输出。
- 不重写官方 API，也不绕过官方登录。

### Q3：为什么要独立开源项目，而不是放在当前调度器里？

回答：因为目标用户不只是当前本机 App 用户，而是其他使用 agent/skill 的人。

独立项目需要具备：

- 可克隆。
- 可安装。
- 可运行测试。
- 可通过 GitHub README 学会使用。
- 可作为 skill 被 agent 引用。

### Q4：自动发现即梦 CLI 是不是 P0？

回答：是。

验收含义：

- 已安装时，`dreaminaq doctor` 能找到 CLI 路径和版本。
- 未安装时，能判断缺失并进入安装流程。
- 用户自定义路径时，能通过配置或环境变量指定。

### Q5：自动安装即梦 CLI 是不是 P0？

回答：是，但要按“官方渠道 + 平台 adapter + 可恢复阻塞”的方式做。

不可做：

- 不下载来路不明的二进制。
- 不把第三方安装脚本静默执行到用户系统里。
- 不在无法确认来源时假装已经自动安装。

应该做：

- 首选官方安装命令。
- 如果需要用户确认，明确显示将执行的命令。
- 安装完成后重新 doctor。
- 如果安装需要网页登录或人工步骤，记录 blocking 状态，用户完成后可继续。

### Q6：自动提醒登录/触发登录是不是 P0？

回答：是。

边界：

- 工具可以检测未登录。
- 工具可以调用官方 CLI 的登录命令或打开官方登录入口。
- 工具可以暂停队列并等待登录完成。
- 工具不接管密码、验证码、扫码内容和 Cookie。

### Q7：夜间长时间不休眠是不是 P0？

回答：是。

这是用户明确补充的第一版关键价值：如果晚上调度跑不起来，项目就没有作用。

验收含义：

- macOS 至少要支持 `caffeinate` 或等价 keep-awake。
- worker 日志能显示 keep-awake 启停。
- 队列未完成时保持唤醒，队列结束后释放。

### Q8：查记录需要查到什么程度？

回答：第一版至少要覆盖 agent 调用和人工排查的核心记录。

需要：

- 任务列表。
- 单任务详情。
- 提交尝试。
- submit_id。
- 队列位置或远端状态。
- 错误摘要。
- 结果路径或 URL。
- 最近事件。

不需要：

- 完整 GUI 日志中心。
- 复杂筛选报表。
- 多用户审计。

### Q9：是否默认复用历史生成结果？

回答：否。

原因：视频生成常常需要多个候选。相同参数再次提交，不一定代表想复用旧结果。

推荐行为：

- `--idempotency-key` 相同：返回同一个任务。
- 无 idempotency key：默认新建任务。
- `--reuse exact`：才复用相同 request hash 的成功结果。

## 推荐第一版切线

第一版只做一条能真正闭环的路径：

```text
安装 dreaminaq
  -> doctor 自动发现/安装即梦 CLI
  -> 检测登录，未登录则触发官方登录
  -> submit 入队
  -> worker --keep-awake 夜间推进
  -> status/history/result 查询
  -> agent skill 文档指导调用
```

不要在第一版做：

- 桌面 App。
- 大型 Web 监控台。
- 旧数据迁移。
- 多账号管理。
- PyPI 发布自动化。
- 完整 MCP Server。

## 结论

这个项目值得独立维护，但它的产品定义要克制：**不是“另一个即梦客户端”，而是“即梦 CLI 的 agent 时代队列层”**。
